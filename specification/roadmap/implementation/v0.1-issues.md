# v0.1 — GitHub Issues

Issues for phase **v0.1 — Walking skeleton (M0)** (version **v0 — Proof: the walking skeleton**),
derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md) (§v0.1) and the
contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md) (§Overview, §Components, §Page model,
§Protocol, §Contracts, §Stack and repository layout, §Deployment and test topology, §Testing and CI).
This file is scoped to a single phase; it opens the sequence (**SLATE-001…008**).

v0.1 puts the whole concept on the desk once and answers the project's only open question: does
LVGL's XML module build and run on the ESP32-P4. It builds a counter whose value lives on the
server, a 1 Hz clock proving unsolicited push, and a throwaway `doc-view` v0 proving the platform's
heaviest renderer first — over a trimmed wire (`subscribe`/`data`/`event` only). Its code is
**quarry, not foundation**: the firmware and server halves live under `m0/`, deliberately outside
the kept `firmware/`/`server/` trees that begin at v1.1. Only `tools/` (the fake device) and
`tests/` are seeded here to be extended forever after.

### SLATE-002 — `LV_USE_XML` on the ESP32-P4 — the go/no-go verdict

**Description:**
The one open question in the specification's §9, and the reason v0.1 exists at all. Enable LVGL's
XML module on the P4, confirm the vendored expat compiles, and instantiate one hand-written page
into a live widget tree. Touches `m0/firmware/`.

**What needs to be done:**
- Enable `LV_USE_XML` in `lv_conf.h`/`sdkconfig` and confirm LVGL's vendored expat compiles for the
  P4 toolchain; resolve any missing-symbol or heap-configuration fallout.
- Write one hand-written M0 page (`m0/apps/m0.xml`) using `lv_xml`'s **native flex attributes** for
  centring — raw LVGL widgets only, no `<component>` definitions, no tokens, no components
  ([ui-implementation.md §6](../../ui-implementation.md)). It names the three dynamic ids the
  applicator will look for: `count`, `clock`, `doc`.
- Register and instantiate it via `lv_xml_component_register_from_file` + `lv_xml_create`, rendering
  from a string or SPIFFS-embedded copy — **no HTTP and no cache yet**, that is SLATE-006.
- **Measure, for the ledger:** page parse time (µs), widget-tree heap cost (bytes, before/after
  `lv_xml_create`), and free heap after render. Log them in a machine-greppable form.
- **If `lv_xml` does not build or run:** stop, record the negative verdict with the exact failure,
  and implement the specified fallback — a vendored ~6 KB SAX parser with the M0 vocabulary
  hand-mapped to `lv_*` calls. Do not silently work around it; the verdict is a deliverable either
  way and changes v1.3's component machinery.

**Dependencies:** SLATE-001

**Expected result:**
A definitive, measured go/no-go on `lv_xml` for the ESP32-P4, with the M0 page rendering on the
panel from XML (or from the fallback parser, with the failure recorded).

**Acceptance criteria:**
- [ ] The hand-written M0 page renders on the Tab5: title, counter value, `+1` button, clock label,
      and an empty document panel, laid out by flex with no pixel coordinates.
- [ ] Parse time, widget-tree heap cost, and post-render free heap are measured and logged.
- [ ] The verdict is unambiguous and recorded — **go** (with the measurements) or **no-go** (with
      the failure and the working SAX fallback).
- [ ] **On-device check:** the render is verified on the USB-attached Tab5, not in a host build.

### SLATE-003 — Trimmed-wire server: page over HTTP, `subscribe`/`data`/`event`, counter + clock

**Description:**
The server gate, and a **seam issue**. A single-file Python asyncio server (~150 lines) serving the
M0 page over HTTP GET and speaking the trimmed wire over WebSocket — `subscribe`, `data`, `event`
and nothing else. Carries the counter handler and the 1 Hz clock ticker. Touches `m0/server/` (new)
and `specification/ARCHITECTURE.md`.

**What needs to be done:**
- Create `m0/server/` with a single-file asyncio server. Use the standard library plus `websockets`;
  **this is not the v1.1 framework decision** — [ARCHITECTURE.md](../../ARCHITECTURE.md) §Stack
  reserves the aiohttp-vs-FastAPI choice for v1.1 and this file is quarry.
- `GET /apps/m0.xml` serves the page XML. No `ETag`, no conditional GET, no cache — v1.1's concern.
- `GET /ws` accepts the WebSocket. **No `proto`/`screen` connect params** — the connect-URL contract
  lands at v1.2; v0.1 implements a strict subset of the wire, never a variant of it.
- Implement the three message types exactly as
  [slate-vision.md §4](../../slate-vision.md) specifies them: `subscribe` (`session_id`, `req_id`,
  `page`, `widgets`), `data` (`session_id`, optional `req_id`, `updates[]` of `{id, <prop>: value}`),
  `event` (`session_id`, `action`, `source`, `values`).
- Honour the closed dynamic-property set: v0.1 uses `text` (SLATE-003) and `items` (SLATE-004) only.
- Counter handler: state is a server-side integer; `event` with `action: "increment"` bumps it and
  pushes `data` with `{"id": "count", "text": "<n>"}`. **The device is never told to compute it.**
- Clock ticker: an asyncio task pushing `{"id": "clock", "text": "HH:MM:SS"}` once a second with
  **`req_id` omitted** — the unsolicited-push proof.
- `subscribe` replies with a `data` frame carrying the current values of the named widgets, with
  `req_id` echoed.
- Unknown message types and unknown JSON keys are **ignored, not errors**
  ([ARCHITECTURE.md](../../ARCHITECTURE.md) §Protocol) — forward compatibility starts here.
- Update [ARCHITECTURE.md](../../ARCHITECTURE.md) §Protocol to state that v0.1 speaks a
  three-message subset with no connect params, so the doc matches what is built.

**Dependencies:** None

**Expected result:**
`python m0/server/server.py` serves the M0 page and holds a WebSocket that answers `subscribe`,
accepts `increment`, and pushes the clock every second.

**Acceptance criteria:**
- [ ] `GET /apps/m0.xml` returns the page; `GET /ws` upgrades and stays open.
- [ ] `subscribe` for `["count","clock"]` returns one `data` frame with both, `req_id` echoed.
- [ ] `event` `increment` is followed by a `data` frame with the new count; the count lives only on
      the server.
- [ ] The clock pushes once a second with `req_id` **absent**.
- [ ] **Contract test:** the three trimmed-wire message shapes (`subscribe`/`data`/`event`) and the
      `text` property, pinned as schema assertions — the seam changes only when this test changes.
- [ ] **Contract test:** an unknown message type and an unknown JSON key are both ignored without
      error or disconnect.
- [ ] **Unit test:** counter handler (increment from arbitrary start) and clock formatter, with the
      clock's time source injected so the test is deterministic. No live network, no paid APIs.
- [ ] `specification/ARCHITECTURE.md` §Protocol records the v0.1 subset.

### SLATE-004 — `doc-view` v0 server side: Markdown → typed blocks pushed as `items`

**Description:**
A **seam issue** pinning the `doc-view` block kinds. The server parses one hard-coded `.md` file
into a list of typed blocks and pushes them as a single `items` update — the structured half of the
trimmed wire, next to the counter's scalar `text`. Touches `m0/server/` and
`specification/ARCHITECTURE.md`.

**What needs to be done:**
- Add a hard-coded source document under `m0/server/`. Per
  [ui-m0-brief.md](../../ui-m0-brief.md): the opening of a real README — a heading, two short
  paragraphs, a 3-item bullet list, two code lines — and **one Ukrainian sentence**, which will
  render as tofu on the device on purpose.
- Make it long enough to matter: **~50 blocks**, so SLATE-007 and the ledger can measure render time
  and scroll feel against the number the roadmap names.
- Implement Markdown → blocks emitting exactly the contracted kinds from
  [ARCHITECTURE.md](../../ARCHITECTURE.md) §Contracts: `h1 h2 h3 p bullet code quote divider`.
  Each block is `{kind, text}`.
- **Out of scope:** the `link` key and inline formatting. Block-level links arrive with the Markdown
  browser at v2.4; inline links are a refused design line.
- Push the whole list as **one** `data` update: `{"id": "doc", "items": [...]}`. Sent in response to
  a `subscribe` naming `doc`.
- **The device never parses Markdown** — this is the invariant the issue exists to establish.
- Record the `doc-view` block kinds in [ARCHITECTURE.md](../../ARCHITECTURE.md) as pinned at v0.1
  (§Contracts already names them; confirm it matches what the parser emits and correct either side).

**Dependencies:** SLATE-003

**Expected result:**
A `subscribe` naming `doc` returns one `data` frame whose `items` is the parsed document, ~50 typed
blocks, ready for a renderer that knows nothing about Markdown.

**Acceptance criteria:**
- [ ] `subscribe` naming `doc` yields exactly one `data` frame with an `items` array.
- [ ] Every emitted block's `kind` is in `{h1,h2,h3,p,bullet,code,quote,divider}` — no other kind
      can escape the parser.
- [ ] The document is ~50 blocks and contains the Ukrainian sentence verbatim.
- [ ] **Contract test:** the `doc-view` block-kind set is pinned; adding a kind fails this test.
- [ ] **Contract test:** `items` is delivered as a single update inside a `data` frame, matching the
      closed dynamic-property set.
- [ ] **Unit test:** Markdown → blocks over a fixture covering all eight kinds, including a fenced
      code block, a blockquote, a rule, and the Cyrillic line preserved byte-for-byte.
- [ ] `specification/ARCHITECTURE.md` agrees with the parser's emitted kinds.

### SLATE-006 — Device half: boot fetch, wire client, mini-applicator, counter, clock, three states

**Description:**
The join, and the issue that makes the concept visible. The device fetches the page over HTTP at
boot, opens the trimmed wire, applies targeted updates through a hard-coded mini-applicator, and
sends the button's event. Touches `m0/firmware/`.

**What needs to be done:**
- Hard-code the server address in firmware config (`192.168.1.197`) and bring up WiFi. **No cache,
  no revalidation, no SD** — v1.1's concern.
- At boot: fetch `GET /apps/m0.xml`, register and instantiate it with `lv_xml` (or the SLATE-002
  fallback).
- Open the WebSocket and send `subscribe` for `["count","clock","doc"]` with a device-minted
  `session_id` and a `req_id`.
- **The mini-applicator:** an id → widget map built at render time; on `data`, look up each update's
  `id` and apply `text` (set the label) or `items` (rebuild the label column — SLATE-007). An update
  naming an unknown `id` is **dropped and debug-logged, never a crash**
  ([ARCHITECTURE.md](../../ARCHITECTURE.md) §Error handling). Hard-coded to `count`/`clock`/`doc` is
  correct here — the general applicator arrives at v1.2.
- One registered event callback on the `+1` button sending `{"type":"event","action":"increment",
  "source":"increment_btn","values":{}}`.
- **The philosophy must be visible on screen:** the button's pressed state is instant and local; the
  number changes only when the server's `data` frame returns. Do not optimistically update the label.
- The three firmware-drawn states and **nothing else**: `connecting…`, `server unreachable` (plain
  centred error text), and the page.
- Match the M0 board exactly ([ui-m0-brief.md](../../ui-m0-brief.md),
  [ui-implementation.md §6](../../ui-implementation.md)): `#e0e0e0` ground, plain `Slate M0` title,
  the count at ~80 px, a **stock** `+1` button with a visible pressed state, a plain clock label,
  default LVGL theme and font throughout. **If it starts looking designed, the milestone has
  drifted** — no tokens, no components, no chrome, no status bar.

**Dependencies:** SLATE-002, SLATE-003

**Expected result:**
Power on the Tab5 and the page arrives from the server, the clock ticks, and the button increments a
count that lives on the server.

**Acceptance criteria:**
- [ ] Boot shows `connecting…`, then the page fetched over HTTP from `192.168.1.197`.
- [ ] With the server down, the device shows `server unreachable` as plain text and does not hang or
      reboot.
- [ ] The clock label advances once a second from unsolicited pushes.
- [ ] Pressing `+1` shows an **instant local pressed state**; the number changes only when the
      server's `data` returns.
- [ ] **A `data` update naming an id not on the page is dropped and debug-logged** — verified by
      pointing the fake device's server at a bogus id.
- [ ] The screen matches board `M0-1`: grey ground, stock widgets, default font, no chrome.
- [ ] **On-device check:** all of the above demonstrated on the USB-attached Tab5.

## v0.1 scope notes

**Total effort:** ~28 points (3 × L, 4 × M, 1 × S) — roughly 4–6 weeks of single-track work, with
the firmware and server chains running in parallel.
**Critical path:** SLATE-001 → SLATE-002 → SLATE-006 → SLATE-007 → SLATE-008.
**Phase DoD (roadmap §v0.1):** power on → the page appears from the server → the clock ticks → the
button increments the count → the document renders and scrolls under a finger — and rebooting the
device does not reset the counter, because the count never lived there. The ledger is written; the
scaffolding is green on the host.

**Contracts pinned this phase:**
- The trimmed wire — `subscribe`/`data`/`event` message shapes (SLATE-003, contract test).
- Forward compatibility — unknown message types and keys ignored (SLATE-003, contract test).
- The dynamic-property set as exercised at v0.1: `text` (SLATE-003) and `items` (SLATE-004).
- `doc-view` block kinds — `h1 h2 h3 p bullet code quote divider` (SLATE-004, contract test).

**Out of scope (deliberately deferred, do not pull forward):** the SD page cache and `If-None-Match`
(v1.1); the connect-URL params `proto`/`screen`, the session registry, and reconnection (v1.2);
components, tokens, fonts, and the manifest (v1.3); `navigate`, history, and the action registry
(v2.2); the shell, `notice`, and the status bar (v3.1); the validator (v5.1). v0.1 speaks a strict
**subset** of the protocol, never a variant of it.

**Quarry, not foundation:** v0.1's firmware and server live under `m0/`. The kept `firmware/` and
`server/` trees begin at v1.1 and are not seeded from this code
([ARCHITECTURE.md](../../ARCHITECTURE.md) §Stack, [ROADMAP.md](../../ROADMAP.md) §v1). Only
`tools/` and `tests/` are kept from this phase.

**Test note:** **no paid APIs and no live network in any suite** — the **fake device** (`tools/`)
drives the wire and the clock's time source is injected. v0.1 runs pytest **locally**, the documented
pre-v1.1 bootstrap exception; from v1.1 the server suite runs only on `192.168.1.197` via
`tools/deploy` (sync → remote pytest → restart on green). On-device checks run from Claude Code
against the USB-attached Tab5 (`idf.py flash` / `idf.py monitor`), and the DoD is demonstrated on
hardware, not reviewed in code.
