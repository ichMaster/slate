# v0.1 — Test plan

Manual and scripted cases that close the v0.1 Definition of Done. Work through
them in order; each says what to run, what to expect, and what to record.

> **Prerequisite for §C onward:** the ESP32-C6 must be running `esp_hosted`
> co-processor firmware, or the device has no network. See
> [the ledger §6](v0.1-poc-ledger.md) — this is currently **unresolved** and
> blocks every network case. §A and §B pass today.

**The DoD** (ROADMAP §v0.1): power on → the page appears from the server → the
clock ticks → the button increments the count → the document renders and scrolls
under a finger — and rebooting the device does not reset the counter.

## The harness

All commands run from the repository root. Every one writes evidence into
`tools/evidence/<timestamp>/`.

```bash
./tools/m0test.sh doctor     # check the environment first
./tools/m0test.sh host       # host suite: pytest + fake device
./tools/m0test.sh serve      # start the M0 server (leave running)
./tools/m0test.sh flash      # build and flash the Tab5
./tools/m0test.sh monitor 30 # capture the device log for 30s
./tools/m0test.sh ledger     # extract SLATE_LEDGER lines from the last capture
./tools/m0test.sh count      # ask the server what the counter is
```

`monitor` prints "interact with the device now" — that is your cue to touch,
press, and scroll while it records.

## §A Host — no hardware needed

### A1 · The host suite is green and deterministic

```bash
./tools/m0test.sh host
```

**Expect:** `94 passed`. Run it three times; the count must not change and no
test may become slow or flaky.

**Record:** pass/fail + the count.

---

### A2 · The two suites stay separate

```bash
pytest -q                                            # product suite
cd codegen && ../.venv/bin/python -m pytest tests    # tracking suite
```

**Expect:** `94 passed` and `546 passed, 17 skipped` respectively. If the first
number jumps to ~640, `testpaths` has been lost and the product run is sweeping
in `codegen/`.

---

### A3 · The counter lives on the server

```bash
./tools/m0test.sh serve      # terminal 1, leave running
./tools/m0test.sh count      # terminal 2
python tools/fake_device.py --increments 3 --watch 0
./tools/m0test.sh count
```

**Expect:** the count rises by exactly 3, and the second `count` call — a **new
connection with a new `session_id`** — still sees it. That is the milestone's
whole point in host form.

**Record:** the before/after values.

---

### A4 · The clock pushes unprompted

```bash
python tools/fake_device.py --increments 0 --watch 5
```

**Expect:** roughly five `push` lines, one per second, each carrying `clock` and
**no `req_id`**. An unsolicited push must never echo a request id.

---

### A5 · The document crosses the wire in one frame

```bash
python tools/fake_device.py --increments 0 --watch 0
```

**Expect:** `doc: 55 blocks`. One frame, ~7.5 KB, all eight block kinds, and the
Ukrainian sentence intact.

## §B Device — no network needed

Flash first:

```bash
./tools/m0test.sh flash
./tools/m0test.sh monitor 30
```

### B1 · Boot, display and touch

**Do:** touch the screen in several places while `monitor` is recording.

**Expect on screen:** grey `#e0e0e0` ground, plain black text. Deliberately ugly
— stock LVGL theme, no chrome. *If it looks designed, the milestone has drifted.*

**Expect in the log:**
```
display 1280x720, touch ready
touch x=<...> y=<...> (pressed)
```
Coordinates must fall inside 1280×720 and track where you actually touched.

**Record:** touch event count (`m0test.sh ledger` prints it).

---

### B2 · Board identification

**Expect in the log:**
```
SLATE_LEDGER i2c_devices=9 addrs=0x10 0x28 0x32 0x40 0x41 0x43 0x44 0x55 0x68
SLATE_LEDGER panel_revision=ST7121 touch=ST712x st712x_fw=1
Discovered board version 3 (LCD ST7121, Touch ST712x, FW 1)
```

**Pass:** our probe and the BSP's own line **agree**. A disagreement means the
probe has drifted from the BSP and must be fixed, not reinterpreted.

**Note:** `0x28` and `0x55` appear only because the LCD rail is powered before
probing — see [ledger §2](v0.1-poc-ledger.md).

---

### B3 · The `lv_xml` verdict

**Expect:**
```
SLATE_LEDGER lv_xml=GO lvgl=9.4.0
SLATE_LEDGER xml_register_us=<~1000> xml_create_us=<~3500>
SLATE_LEDGER lv_pool_total=62780 lv_register_cost=1288 lv_widget_tree_cost=1912
```

**Pass:** `lv_xml=GO`. Any `NO_GO` or `UNAVAILABLE` is a project-level event —
stop and re-read [ledger §1](v0.1-poc-ledger.md) before continuing.

**Record:** the four numbers, so drift across later phases is visible.

---

### B4 · No page, no server → the unreachable state

**Do:** with **no server running**, reboot the device (`monitor` again).

**Expect on screen:** `connecting…`, then plain `server unreachable`. The device
must not hang, reboot-loop, or show a partial page. Two states, no third.

---

## §C Device + server — the DoD

> Blocked until the C6 runs esp_hosted firmware ([ledger §6](v0.1-poc-ledger.md)).

Start the server and leave it running, then flash and monitor.

```bash
./tools/m0test.sh serve       # terminal 1
./tools/m0test.sh monitor 60  # terminal 2
```

### C1 · The page arrives from the server

**Expect in the log:**
```
SLATE_LEDGER wifi_ip=<address>
SLATE_LEDGER page_fetch_bytes=<~1872> from=http://<host>:8000/apps/m0.xml
subscribed as s-<hex> — the server owns the screen now
```

**Expect on screen:** the title, a large number, a `+1` button, a clock, and a
white document panel.

**Pass:** the page is **fetched**, not compiled in. Stop the server, reboot, and
B4's unreachable state must appear instead.

---

### C2 · The clock ticks

**Watch the clock label for ~10 s.**

**Expect:** it advances once per second, from unsolicited pushes. The device has
no clock of its own — if it ticks with the server stopped, something is wrong.

---

### C3 · The button increments — and where the truth lives

**Do:** press `+1` five times, slowly, watching closely.

**Expect:**
- the button shows its pressed state **instantly** (local, LVGL);
- the number changes only **after** the server's frame returns — a visible beat
  later on a slow link.

**Pass:** press feedback is immediate **and** the number is not optimistic. If
the number changes on touch-down, the device is holding truth and the invariant
is broken.

**Cross-check:** `./tools/m0test.sh count` from another terminal must report the
same number as the screen.

---

### C4 · The document renders and scrolls

**Do:** drag the document panel up and down.

**Expect on screen:** headings larger, `•` bullets, code on a light-grey strip,
quotes indented, a hairline divider. A thin scrollbar, and content **visibly cut
at the panel's bottom edge**.

**Expect the Ukrainian sentence to render as empty boxes (tofu).** This is
correct — the stock font is Latin-only and the board draws it that way on
purpose. **Do not fix it in M0**; real fonts arrive at v1.3.

**Expect in the log:** `SLATE_LEDGER doc_blocks=55 doc_render_us=<n> doc_heap_free=<n>`

**Record:** `doc_render_us`, and whether scrolling feels smooth under a finger.
Both go in [ledger §5](v0.1-poc-ledger.md).

---

### C5 · Repeated updates must not leak

**Do:** let the device run 5 minutes with the server pushing.

**Expect:** `doc_heap_free` stays flat across rebuilds. A steady decline means
the column is not being freed.

---

### C6 · **The reboot proof** — the milestone

**Do:**
1. Press `+1` until the number is memorable (say 7).
2. Note it. Run `./tools/m0test.sh count` to confirm the server agrees.
3. **Power-cycle the Tab5.** Leave the server running.
4. Wait for the page.

**Expect:** the counter shows **7**, not 0.

**Pass:** the number survived, *because it never lived on the device*. This is
the philosophical point of the whole milestone — if it resets, v0.1 has failed
regardless of everything else passing.

**Then the converse:** restart the **server** and reboot the device. The count
returns to 0, because that is where it lived.

**Record:** both values, before and after each restart.

---

### C7 · An unknown id is dropped, never a crash

**Do:** with the device running, send an update naming a widget the page lacks:

```bash
.venv/bin/python - <<'PY'
import asyncio, json, sys
sys.path.insert(0, "m0/server")
# Point the running server at a bogus id by hand, or temporarily add
# make_update("nonesuch", text="x") to a subscribe response.
PY
```

**Expect:** the device logs a debug line and carries on. No crash, no reboot, no
blank screen. A server that has drifted ahead of a cached page is a normal
condition, not an exceptional one.
