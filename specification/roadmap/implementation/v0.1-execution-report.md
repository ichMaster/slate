## Architecture impact

Five edits, each landing with the work that made it true:

1. **§Protocol** — the v0.1 subset stated explicitly: three messages, plain
   `GET /ws` with no connect params, no session registry, no `ETag`. The
   absences read as deferred rather than missing.
2. **§Stack and repository layout** — names the **`m0/`** quarry tree. The spec
   said v0.1's code was quarry but never said where quarry lived.
3. **§Contracts** — the eight `doc-view` block kinds are pinned by contract test
   from v0.1; `link` arrives at v2.4.
4. **§Deployment and test topology** — the account (`ich@ich-picobox`), the SSH
   alias, **port 8010** (`roboface_server` owns 8000 on that host), and the fact
   that the workstation *cannot* host the server: its endpoint filtering accepts
   the connection and destroys the socket before the first read.
5. **ui-implementation.md §6 and ui-m0-brief.md** — the type sizes as built,
   replacing two guesses: the count is 48 px (the largest stock Montserrat, with
   ~80 px recorded as a requirement on `stat-value` at M3) and the document
   panel is 68 %, not 55 %, because 55 % assumed the 14 px default.

## What the milestone actually cost, and where

The five firmware issues were held up by faults that all presented as something
else. Recorded because each will recur:

- **The touch controller does not appear on I2C until the LCD rail is powered**,
  and the BSP's own detection enables only the touch rail — so it asserts and
  boot-loops on board version 3.
- **P4 silicon v1.3 splits the build.** IDF 5.5 defaults to requiring v3.1+ and
  treats `<3.0` and `>=3.0` as mutually exclusive targets.
- **LVGL removed the XML module in 9.5.0**, and the BSP's dependency graph
  resolves there by default — producing a platform with no XML renderer at all.
- **The SDIO pins in `esp_hosted` belong to the P4 eval board**, the visible pin
  options silently ignore assignment, and the reset line is active high. Three
  faults stacked, and together they looked exactly like a co-processor with no
  firmware.
- **`lv_xml` ignores unregistered font names silently**, so sizes set in XML did
  nothing while the same sizes set from C worked.

Two of the harness's own defects also mattered: a `grep -c` miscount gave a
healthy device a false FAIL, and attaching the monitor reset the device at the
exact moment the operator was told to start touching, which read as a crash.

v1.1 starts the kept `firmware/` and `server/` trees. It should carry forward
from here: the LVGL 9.4 pin, the Tab5 SDIO pin set and reset polarity, the
