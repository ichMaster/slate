## The blocker

Every blocked issue carries an on-device acceptance criterion, and no ESP32
enumerates on this workstation's USB.

```
$ ls /dev/cu.* | grep -v bluetooth
(none)

$ ioreg -p IOUSB -l | grep "USB Product Name"
USB2.0 Hub · USB3.0 Hub · USB Billboard Device · USB 10_100_1000 LAN
```

No Espressif USB-JTAG, no CH34x/CP210x bridge. [ARCHITECTURE.md](../../ARCHITECTURE.md)
§Deployment and test topology fixes the Tab5 as permanently USB-attached to the
workstation, and §Testing and CI puts every firmware check there; the phase DoD
is a hardware demonstration, not a code review. Nothing in the firmware chain
can be honestly closed without it.

**The toolchain is no longer the blocker.** ESP-IDF **v5.5.5** and the RISC-V
toolchain were installed during this run (`~/esp/esp-idf`, `idf.py --version`
reports `ESP-IDF v5.5.5`), so `idf.py build` will work the moment the device
appears. Only the device is missing.

## Detailed results

### SLATE-003 — Trimmed-wire server
**Status:** completed · **Commit:** `ff31f59`
**Validation:** ✅ pytest 30 · ✅ mypy strict · ✅ ruff · ✅ live HTTP + WS smoke

`m0/server/server.py`: HTTP and the WebSocket share one port through the
`websockets` `process_request` hook, which is what keeps the file at skeleton
size. The counter is a server-side integer; the clock is an asyncio ticker
pushing with `req_id` omitted.

**Seams pinned:** the `subscribe`/`data`/`event` message shapes; the closed
dynamic-property set as v0.1 exercises it; the guarantee that unknown message
types and keys are ignored rather than errored.
